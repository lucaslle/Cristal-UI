## Multiple selection

With `multiple`, each option shows a checkbox and the list stays open while selecting. Values are read and set with `values` (an array), and `onCrChange` gives the array in `event.detail`. The form submits each value under the same `name`, like a native `<select multiple>`: read them with `formData.getAll('languages')`.

## Search

With `searchable`, a search field appears at the top of the open list and filters options as you type, ignoring accents and case: "ev" finds "Évry". In each option, the letters that match the search turn bold, in the theme colour (`::part(match)` to style them). Typing on the closed list opens it directly with the search filled in. `searchable` can be combined with `multiple`.

## Server-side search

When options come from an API, add `remote` to `searchable`. The list no longer filters anything itself: it emits `onCrSearch` with the typed text (`event.detail`), 300 ms after the last keystroke so the API is not called on every letter, and shows exactly the `<option>` elements you give it. During the call, `loading` shows and announces "Searching…".

- On close, the search is cleared and `onCrSearch` is emitted with an empty text: restore your default options then.
- Selected options keep their label in the button even when they are no longer part of the results, including with `multiple`.
- Ignore responses that arrive out of order: only the latest search counts (see `latest` in the example).

The example queries the French public API of municipalities (geo.api.gouv.fr), by name or by postal code.

## Keyboard

| Key | List closed | List open |
|---|---|---|
| Down / Up Arrow | opens the list | next / previous option |
| Enter, Space | opens the list | selects the option and closes |
| Home / End | — | first / last option |
| Letters | opens and moves to the option starting with those letters | moves to the matching option |
| Escape | — | closes without changing the value |
| Enter, Space (with `multiple`) | — | checks or unchecks the option, the list stays open |
| Tab | moves to the next field | selects the option and moves to the next field |

## Validation

With `required`, form submission is blocked until an option is chosen, and the message "Choose an option from the list." is shown ("Choose at least one option from the list." with `multiple`). The `error` property replaces this message.

`error-animation` animates the error when it appears and on every rejected submit (zigzag, badge, echo…): see [Animated error](/docs/composants/champ-texte#animated-error).

## Accessibility

- Follows the W3C "combobox" pattern (ARIA Authoring Practices): focus stays on the field, and the active option is announced through `aria-activedescendant`.
- The label, hint and error are read by screen readers, as for the text field.
- The list is displayed above the page: it is never clipped by a scrolling container or a modal, and opens upward when there is not enough room below.
- Clicking outside the list closes it.

- With `multiple`, the list is announced as "multi-selectable" (`aria-multiselectable`) and each option as checked or not.
- With `searchable`, the search field is labeled "Search the list", the active option is still announced while typing, and "No results" is read when nothing matches. In the field, Space types a space: select with Enter.
- With `remote`, the list is marked busy (`aria-busy`) during `loading`, and "Searching…" is read.
