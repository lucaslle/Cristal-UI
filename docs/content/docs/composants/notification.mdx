## Example

Put a single `CrToaster` area in the page (fixed at the bottom right) and add one `CrToast` per message to it: it slides in from the corner, a bar empties for `duration` milliseconds (5000 by default), then it closes. Remove it from your list in `onCrClose`.

| `variant` | Use |
|---|---|
| `info` | neutral information (default) |
| `success` | an action succeeded |
| `danger` | an error; read immediately by screen readers |

With `duration={0}`, the toast stays until it is closed: prefer it for an error, which must leave time to read and act. It closes with the Close button, Escape, or by dragging it sideways.

A single, always-present toast works too: drive it with `open`, and set your state back to `false` in `onCrClose`.

<Callout>
  If the user asked their system to reduce motion, the toast fades in and out without sliding. The remaining-time bar keeps emptying, slowly and smoothly: it tells how long is left to read.
</Callout>

## Accessibility

- Each toast is a live region: `role="status"` (read once the screen reader finishes its sentence), or `role="alert"` with `variant="danger"` (read immediately). The region exists, empty, before the message so the announcement is not lost.
- The toast does not take focus: the user can keep working.
- Time stops while the pointer hovers the toast or focus is inside it (WCAG 2.2.1); the bar stops with it.
- The close button is named "Close" ("Fermer" in French); Escape closes the toast when focus is inside. Dragging therefore always has a keyboard and single-click alternative.
- The type is not conveyed by colour alone: a different icon (i, ✓, !) comes with it, and the message should say it.
