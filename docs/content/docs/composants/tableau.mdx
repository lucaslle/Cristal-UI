## Example

Each user arranges the table to their liking: drag a header to move the column, drag the right edge of a header to change its width (double-click to fit it to the content), choose the displayed columns in "Columns" and the row height with "Comfortable", "Normal" or "Compact". "Reset" goes back to the initial layout.

## Styles

The `variant` property changes the look of the table; pick one in the example above:

| Value | Look |
|---|---|
| `default` | tinted header, thin lines between rows, light shadow (default) |
| `striped` | alternating rows, no lines |
| `cards` | each row is a card laid on a tinted background, with a purple border on hover |
| `minimal` | no frame or header background, a bold line under the titles |
| `grid` | every cell has a border, spreadsheet-style; the hovered cell is outlined |

Headers stay stuck at the top when the table scrolls: set its height with the `--cr-table-max-height` CSS variable (for example `400px`).

## Status badges

With `badges`, a column displays some values as colored badges: `{ Paid: 'success', Pending: 'warning' }`. Available tones: `primary`, `success`, `warning`, `danger`, `neutral`. The text stays readable (contrast of at least 4.5:1) and color is never the only information: the value is always written out.

## Columns and rows

`columns` describes the columns, in their initial order:

| Field | Description |
|---|---|
| `key` | key of the value in each row (required) |
| `label` | column title (required) |
| `width` | width in pixels, 160 by default (from 64 to 640) |
| `align` | `end` to right-align, for example amounts |
| `pinned` | column pinned to the left, which stays visible when the table scrolls |
| `hidden` | column hidden initially |
| `badges` | values displayed as badges, with their tone |

`rows` is an array of objects, with one value per `key`. Values are displayed as text: format amounts and dates before passing them.

## Large datasets

The table first renders 100 rows, then 100 more each time its end gets close to the screen while scrolling: thousands of rows display without freezing the page. The total is still announced (`aria-rowcount`) and a line below the table reads "100 of 3,685 rows: more appear as you scroll.". When `rows` changes (a filter, another period), the display starts again from the first 100.

## Remembering settings

With `storageKey`, the settings (order, widths, pinned and hidden columns, density) are saved in the browser and restored on the next visit. `onCrLayoutChange` also gives them in `event.detail` on every change, to save them on the server for example.

## Keyboard

Move focus to a header with Tab:

| Key | Action |
|---|---|
| ← → | adjacent header |
| Home / End | first / last header |
| Alt + ← → | moves the column |
| Shift + ← → | narrows or widens the column by 16 pixels |
| Enter | fits the width to the content |
| F | pins the column to the left, or unpins it |
| M | hides the column |

The table footer recalls these shortcuts and summarizes the layout: "6 of 7 columns · 1 pinned · normal rows".

## Animations

- The grabbed column floats above the others, and a purple line shows where it will be dropped.
- After a move, each column slides from its old position to the new one.
- A shadow appears under pinned columns as soon as the table scrolls.

<Callout>
  If the user has asked their system to reduce motion, columns change position without sliding.
</Callout>

## Accessibility

- It is a real table (`table`, `th scope="col"`), named by its title.
- Every mouse setting has a keyboard equivalent, described on each header.
- Every action is announced: "Status moved to position 3 of 7.", "Product pinned to the left.", "Region hidden: 6 of 7 columns.".
- A pinned column is announced as "pinned"; at least one column always stays visible.
- With many rows, the total number is announced even if only the first ones are displayed.
