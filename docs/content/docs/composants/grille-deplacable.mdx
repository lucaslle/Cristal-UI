## Example

Each `CrGridItem` has a title (`label`), a position (`x`, `y`, in cells starting from 0) and a size (`w` columns, `h` rows). The user moves it by grabbing it anywhere (or by its ⠿ handle), and resizes it by dragging its corner: the grid appears, the target slot is drawn with a dashed outline, the other items move aside during the drag, then everything packs upwards.

## Grabbing a card

The `grab` property of `CrGridLayout` chooses how the mouse grabs a card:

| `grab` | Behaviour |
|---|---|
| `surface` (default) | anywhere on the card: dragging starts as soon as the pointer moves |
| `hold` | anywhere, after holding the pointer down for a moment (300 ms) without moving; a click followed by a quick movement selects text as usual |
| `handle` | by the ⠿ handle only |

In every case the ⠿ handle moves the card immediately, and pressing a button, a checkbox, a link, a field or a scrollbar inside the card does not move it. With a finger, on a touch screen, only the handle moves the card: swiping on the card scrolls the page.

| `variant` | Look |
|---|---|
| `card` (default) | bordered card, light shadow |
| `elevated` | no border, a soft shadow that grows on hover |
| `soft` | tinted with the primary colour, coloured title |
| `outline` | outline only, the card shows the background |
| `glass` | frosted glass: put it on a colourful background or an image, light or dark enough for the text to stay readable |

| `resizeHandle` | Handle |
|---|---|
| `corner` (default) | an arc that follows the card's rounded corner |
| `knob` | a round knob on the corner |
| `edges` | the corner, plus the right edge (width only) and the bottom edge (height only); a bar shows on the hovered edge |

## Grid

| `CrGridLayout` property | Role |
|---|---|
| `columns` | number of columns (12 by default) |
| `rowHeight` | height of a row in pixels (80 by default) |
| `gap` | space between items in pixels (16 by default) |
| `editable` | `false` to lock the layout (no handles) |
| `grab` | where the mouse grabs a card: `surface`, `hold` or `handle` |
| `stackBelow` | width in pixels below which items stack (480 by default) |
| `storageKey` | remembers the user's layout from one visit to the next |

`onCrLayoutChange` gives the layout (`id`, `x`, `y`, `w`, `h` of each item) after each change, to save it on the server for example; the `reset()` method goes back to the initial layout.

## Items

- Give each item an `id`: it is what finds the item's place in the saved layout.
- Without `x` or `y`, an item takes the first free slot: handy for adding an item from a list.
- `minW`, `minH`, `maxW` and `maxH` constrain the size; `removable` adds a × button that emits `onCrRemove` (then remove the item from your list).
- The `actions` slot places buttons in the header.
- When the content overflows the card, it scrolls; the area then receives focus (Tab) and can be scrolled with the arrows, Page Down and Page Up.

## Keyboard

On an item's handle (Tab):

| Key | Action |
|---|---|
| ← → ↑ ↓ | moves the item by one cell |
| Shift + ← → | one column less or more |
| Shift + ↑ ↓ | one row less or more |

Each change is announced: "Sales: column 3, row 1.", "Sales: 4 columns by 3 rows.".

## Small screens

Below 480 pixels wide (`stackBelow` to change this threshold), items stack at full width, in grid order, and the handles disappear.

<Callout>
  If the user has asked their system to reduce motion, items change position without sliding.
</Callout>
