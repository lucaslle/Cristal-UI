## Skeleton

`CrSkeleton` draws the shape of the expected content and gently pulses (1.6s). `shape` is `line` (a line of text, default), `block` (image, card) or `circle` (avatar); `width` and `height` take any CSS value.

## Progress bar

Without `value`, `CrProgress` is indeterminate: a segment glides along the track, growing mid-way (1.5s). With `value` (0 to 100), the bar fills up; `showValue` also shows a big percentage that counts up to each new value.

## Processing steps

`CrProgressSteps` shows what is happening during a long wait: past steps are checked, the current step has a spinner, the next ones only appear in turn. `current` is the current step; it equals the number of steps once everything is done.

## Indicator

`CrLoader` signals a wait of unknown length: a spinning circle (default) or, with `variant="bounce"`, a ball that bounces, squashes on landing, and whose shadow shrinks as it rises; with `variant="search"`, a gliding magnifier for searches. Its size follows `font-size`.

## Blur-up image

`CrImage` shows the image blurred (18px) and slightly zoomed in, then sharpens it over 2s once loaded. Give the component a size (`width`, `height` or `aspect-ratio`): the image fills it and stays cropped.

## Accessibility

- `CrSkeleton` is hidden from screen readers: signal loading on the container (`aria-busy="true"`) or with a `CrLoader`.
- `CrProgress` is a progress bar (`role="progressbar"`) named by `label` ("Progress" by default); with `value`, its value is read. The big percentage is hidden so it is not read twice.
- `CrLoader` is a status region that reads `label` ("Loading…" by default).
- `CrProgressSteps` is an ordered list: the current step has `aria-current="step"`, each step is read with its state ("current", "completed") and new steps are announced.
- `alt` is required on `CrImage`; leave it empty (`alt=""`) for a decorative image.
- These animations loop: only show them while loading, and remove them as soon as it is done.
